System Monitor Mocks

Eleven static pages for the workspace's Memory & disk app: the shipped page as it is today, then ten directions that each add CPU and change the layout or the information architecture. Every page uses the workspace's design tokens and the same sample data (an 8 GB machine with three chats open). Pick one on the left; it is framed at 600 x 800 by default, with the shell's real cascade and snapped frames on a laptop desktop as alternatives. Under each name is what the real app would need to become it, since the app has to stay simple and cheap.

Notes

  • The sample data is shared (shared/mock.js): one working chat, two idle ones, a code checker, two user-built apps, one program stopped this morning. Hover a chart for the reading at that time.
  • Each page is self-contained HTML with no build step, like the shipped page, so whichever direction wins can keep that property. The headline figures come from the shared data; some pages hard-code their labels and side facts, so they are pictures rather than renderings.
  • Nothing in the shell gives the app a size of its own: a new window opens at the cascade frame (60% x 70% of the desktop, frames.ts), which is landscape on a laptop. The portrait default here is the size the app is expected to be used at; check the landscape presets before ruling out a two-column direction.
  • Pages 03, 04 and 08 are "app chrome" layouts that fill their window; the rest are the single scrolling column of the current app.
