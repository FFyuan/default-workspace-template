Visiting agents: a coding agent running outside the workspace can be invited in with a one-time code and then works through the workspace with the workspace's own authority. The gateway gains the `/_agent/*` surface on the auth origin (join, me, primer, skills, changes, invites, grants) and admits a bearer admission token beside the session cookie, resolving it against a new agent grant kind kept in `data/.secrets/agent_access/grants.toml` and scoped to the whole workspace (every origin, exec authority through owner-exec via a reconciled `authorized_keys` line) or to named apps. A served single-file Node helper (`wsvisit`) joins, signs owner-exec requests, verifies responses, refreshes the skills index daily, and heals moved coordinates. The `agent-access` CLI exposes invite, list, revoke, primer, skills, changes, and reconcile for the desktop and the terminal; with `--json` its refusals are JSON on stderr, and its audit events record which parent command invoked it. Every writer of `~/.ssh/authorized_keys` (the gateway's reconcile and the desktop's SSH grant) now holds `authorized_keys.lock` around its read-and-write. Caddy routes `/_agent/*` on the auth origin and strips `Authorization` before every backend. Design: `specs/studio-agent-access/spec.md` in the mngr repo. The CLI refuses a non-positive `--expires-in-days` the way the invite route does; the helper refuses a state directory that is not private when it reads from it, tells an app-scope agent that inviting needs the whole workspace instead of calling it revoked, and names the clock skew behind a signature refusal. The CLI's audit events record the chain of commands above it rather than only `uv run`, so a mint the desktop ran over `mngr exec` reads apart from one a visiting agent ran through owner-exec. The helper no longer runs a command a second time when the run's stream trailer fails verification: it refreshes the workspace's addresses for the next command and reports the failure after the output. The helper drains its stdout and stderr before exiting, so a large answer read through a pipe (where Node writes asynchronously on macOS) keeps its tail. The join route bounds the body it reads rather than the body it has already read, and the grants and invites files escape every control character a stored string carries, so a trusted caller's odd input can no longer leave the files unreadable.
