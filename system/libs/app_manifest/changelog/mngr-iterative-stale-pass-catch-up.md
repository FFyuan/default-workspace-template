`pass-scope --lead-ref` records what the branch merged in from the lead after it left the lead's line (a catch-up): `incoming_base`, the newer of where it left and the window's start, and `incoming`, the changed files of the lead's commits from there to the fork point. Both are empty for a branch that merged in none. `select-tests --scope-file` runs, for each incoming file, the suites and npm packages of the pass's own creations it reaches through a declared dependency (a package one depends on, a `uv.lock` upgrade compared from `incoming_base` to the fork point, a shared frontend package one builds), and nothing else: not the changed package's own suite, not its other dependents, and not the full root suite. When an incoming `uv.lock` cannot be compared, every creation's own suite runs, with a note. A pass gate whose branch merged nothing from the lead selects exactly what it did before.
