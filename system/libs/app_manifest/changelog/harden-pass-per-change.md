New `app-manifest pass-scope --creation <type>:<name> [...] [--diff-base REF] [--out FILE]` writes the scope file for a harden pass over several creations: each creation's footprint, and one diff split into the changed files some creation accounts for and those none does. A creation is `app:<name or package>`, `skill:<directory>`, `service:<package>`, or `shared:<path under .agents/shared>`. A standalone service (and an app directory with no `app.toml` yet) is scoped by its directory and, as wiring, the program named after its package plus every `<name>-<role>` program; scope files gain the `service` creation type. A pass that names one creation twice is refused, whether by the same `--creation` or by an app's registered name and its package directory.

`pass-scope --lead-ref REF` tells the pass's own work from other work in its diff window. The diff gains `fork_point` (the newest commit of the lead's first-parent history the branch holds, so a milestone the lead merged does not move it) and `others` (changed files that are neither in a footprint nor the pass's own: what the branch changed since that point, and every file of a lead commit before it that touched a footprint); `outside_footprint` keeps only the branch's own changes. The diff also gains `lockfile_base`, the commit a changed `uv.lock` is compared against: the fork point, or the window's start when one of the pass's commits before the fork changed the lock, so the hardened change's own upgrade is tested. `select-tests --scope-file FILE` selects every changed file except `others`, and refuses a file with no fork point or whose diff does not run to `HEAD`.
