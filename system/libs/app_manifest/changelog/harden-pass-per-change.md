New `app-manifest pass-scope --creation <type>:<name> [...] [--diff-base REF] [--out FILE]` writes the scope file for a harden pass over several creations: each creation's footprint, and one diff split into the changed files some creation accounts for and those none does. A creation is `app:<name or package>`, `skill:<directory>`, `service:<package>`, or `shared:<path under .agents/shared>`. A standalone service (and an app directory with no `app.toml` yet) is scoped by its directory and, as wiring, the program named after its package plus every `<name>-<role>` program; scope files gain the `service` creation type. A pass that names one creation twice is refused, whether by the same `--creation` or by an app's registered name and its package directory.

`pass-scope --lead-ref REF` tells the pass's own work from other work that landed in its diff window. The scope file's diff gains `fork_point`, the newest commit of the lead's first-parent history the ref holds (a milestone the lead merged from the branch does not move it; a lead commit the branch merged in does), and `others`, the changed files that are neither in a footprint nor changed by the branch since its fork point; `outside_footprint` then lists only the branch's own changes. `select-tests --scope-file FILE` selects from such a file: every changed file except `others`, with a changed `uv.lock` compared against the fork point. It refuses a file with no fork point, one whose diff does not run to `HEAD`, and a working tree with uncommitted changes.
