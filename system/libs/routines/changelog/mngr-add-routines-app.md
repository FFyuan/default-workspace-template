New: the routines library, everything in the workspace that runs on a schedule. One TOML definition per routine under `system/routines/`, a scheduler (interval or one-off, time of day, weekdays, day of the month, catch-up after downtime, retry after a failed run), one runner for command runs and skill runs (which wake the routine's own chat and wait for the agent's turn through the chat app), per-routine state, an append-only run ledger with a log per run, notifications to the Imbue Studio feed (headed by the routine's title) after repeated failures, on recovery and when an agent waits on the user, whether the agent was woken by a skill routine or by `routines wake` from a command routine's run, the `routines` command for agents, the cron env wrapper, and `routines migrate-cron`, which converts the cron entries a workspace wrote before. The listing names the apps routines belong to (`app_names`, from the app registry), a run in flight is told from a reused pid by the process's start time, and a spawned run's own output goes to its run log.

`routines wake` names the chat after the routine and waits as long as the routine's `timeout` says when the routine is defined (`--title` and `--timeout` still override), so a command routine that wakes its agent is recorded as a skill run is.

`routines migrate-cron` also converts a plain cron line's weekday lists and ranges (`1-5`, `1,3,5`) and a runner job id with capitals or underscores, leaves an entry whose routine already exists in place, and points every entry it leaves with cron at the env wrapper's new path. The command refuses a `--days` or `--once` it cannot read, a mistyped `--run-id`, and a `routines log` for a run the routine never had, each in one line; an empty `--at`, `--days` or `--app` clears the field on `edit`; a wake inside a run never waits past the run's own time. The Fix brief quotes the last finished run's output. A skill run reads a turn longer than one transcript page to its end, so its summary is the agent's last message and a long turn is never mistaken for one that is still going. A skill run whose agent worked and went idle without answering ends failed a minute later, instead of waiting out the routine's timeout and interrupting an idle chat. A state file that cannot be opened is an error rather than a fresh start, and one whose content does not parse is kept beside the fresh one (`state.json.bad`) when the next write replaces it. `routines add` and `edit` refuse `--every` beside `--once`, and `--skill` beside a command, instead of keeping whichever came last. `routines migrate-cron` converts an entry file whole or not at all, leaves a reversed weekday range with cron, and skips a line whose duration or time of day it cannot read instead of stopping the whole pass.
