The library now owns how a route exchanges JSON, so an app's API document cannot drift from its routes. Every app keeps a route table: a `RouteModels` entry (request model, response model, status, alternate successes) for each route that exchanges JSON and a `SchemalessRoute` entry, with its reason, for each that serves a page, a file, a stream or a socket. `parse_request_body` validates a body with the model the table names (a body off the shape is a 400 `ErrorResponse`, the one error shape every route now answers) and `model_response` answers the model the table names; either disagreeing with the table fails the request with `RouteModelsMismatchError`. The document shows every table entry, `x-no-schema` with the reason for a schemaless route, and `ErrorResponse` as every operation's default response. `assert_api_schema_describes_app` now also requires every operation to be in the table, the table to name no route the app lacks, and no modelled view to read its body around the helper.
