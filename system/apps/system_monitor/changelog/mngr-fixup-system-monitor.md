Memory & disk becomes System Monitor: the app adds CPU and gains a view per resource. The overview shows three tiles (CPU as a share of the cores, memory and disk as a share of their totals, with the last 10 minutes under the first two), the breakdown of what is using the workspace with CPU and memory columns, and the recent events (programs the memory guard stopped, and busy stretches of CPU above 90% with the chats and programs that caused them). The CPU view (`/cpu`) has a chart over 10 minutes, an hour or a day, the breakdown sorted by share, and the busy stretches; the Memory view (`/memory`) is the previous page's content with the guard's 90% mark drawn in; the Disk view (`/disk`) shows the disk, the state of the backups (from the backup service's events, with a link to its README), and measures what is on the disk only when asked.

The graphs now come from the `resource_sampler` program (`system/services/oom_priority`), so they stay whole across the app stopping between windows; the app no longer samples memory itself. New routes: `/api/history?span=1h|24h`, `/api/disk`, and `POST /api/disk/scan`; `/api/stats` carries `cpu`, `events`, both graphs' `history`, and a `cpu` share on every breakdown row.
